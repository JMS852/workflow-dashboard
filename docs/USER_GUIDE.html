1. 核心概念

Dashboard 是什么？

Workflow Dashboard 是一个信差平台。它不产生 AI 内容——只负责在用户和多个 Claude Code / Codex Agent 之间传递消息、汇聚结论并推动辩论和决策。

与传统 AI 工具的根本区别

传统 AI 工具（ChatGPT 等）Workflow Dashboard
AI 来源单一 API 调用多个独立 Claude Code / Codex CLI 实例
工作方式一问一答多 Agent 并行产出 → 互审辩论 → 投票决策
Dashboard 角色AI 执行者（自己调 API）信差——传递消息、汇聚结论
适用任务简单对话复杂工程：算法、数学、架构、嵌入式
Token 效率N/AAgent 间只交换结论 ~200 字，节省 25×+
上下文单次对话每 Agent 保持独立完整上下文，跨轮次记忆

三段式工作流

Round 1 产出  → 用户提任务 → 所有 Agent 并行产出方案 + 200 字结论
Round 2 辩论  → Dashboard 汇聚结论对比表 → Agent 互相评判、改进
Round 3 决策  → Agent 投票 → Dashboard 展示最终决策
📌 三条设计原则：
1. Dashboard 不产生 AI 内容 — 只做消息传递和展示
2. 每个 Agent 在自己的 Session 里完整工作 — 有上下文、有记忆
3. Agent 间 只交换结论（~200 字），不互读完整产出 — 大量节省 Token

2. 安装与启动

2.1 系统要求

操作系统Windows 11 / Windows 10（macOS / Linux 理论兼容）
Node.js18+（推荐 20 LTS）
Python3.12（仅可选 Sandbox 功能需要）
磁盘~500 MB（含 Node 依赖）
网络Agent 运行时需 Claude API / OpenAI API 连接

2.2 安装 CLI 工具（至少一种）

Claude Code CLI

# 方式一：npm 全局安装
npm install -g @anthropic-ai/claude-code

# 方式二：winget (Windows)
winget install Anthropic.ClaudeCode

# 验证
claude --version    # 应显示 2.x.x (Claude Code)

# 认证（二选一）
claude login        # 交互式登录
# 或
set ANTHROPIC_API_KEY=sk-ant-...    # 环境变量方式

Codex CLI（OpenAI）

# 方式一：npm 全局安装
npm install -g @openai/codex

# 方式二：桌面应用安装（附带 CLI）
# 下载：https://github.com/openai/codex/releases/latest

# 验证
codex --version    # 应显示 codex-cli 0.x.x

# 认证
set OPENAI_API_KEY=sk-...

只装一种可以用吗？ 可以。建议至少装 1 种。推荐 Claude Code（对代码/数学任务表现更优）。

2.3 安装 Dashboard

git clone https://github.com/JMS852/workflow-dashboard.git
cd workflow-dashboard
npm install

2.4 启动

node launcher.js

启动后自动：编译 Electron TS → 构建 React 前端 → 检测 CLI → 打开窗口。
关闭窗口 = 缩到系统托盘。托盘图标右键可退出。

2.5 启动故障速查

Cannot find module 'electron'

npm install 未完成。清理重装：rm -rf node_modules && npm install

窗口一闪而过

TypeScript 编译失败。手动检查：npx tsc -p tsconfig.electron.json

3. 首次使用

1
打开项目目录

点击「选择项目目录」。Dashboard 在目录下创建 .multi-ai-workflow/ 存放工作记录。

2
添加 Agent

右侧 Agent 面板点 +，填写：

ID唯一标识，如 cc-arch
类型选择 Claude Code 或 Codex
显示名如 Claude #1（系统架构师） — 这影响 Agent 回答风格
工作目录Agent 执行代码的目录

点「注册」。绿色 ON 标签 = 已启用。

3
提交任务

在输入框输入任务，Enter 发送（Shift+Enter 换行）

4
观察流程

状态栏自动显示 Round 1 → 2 → 3 → 完成。切换到「结论对比」和「辩论&决策」标签查看结果。

4. 管理 Agent

4.1 状态指示

图标状态含义
●idle空闲中
◉working正在执行（脉冲动画）
✓done本轮完成
✗error出错（CLI 崩溃/超时/异常）
⚠不可用CLI 未找到或路径错误

4.2 推荐 Agent 配置

ID类型显示名适合场景
cc-archClaude CodeClaude #1（系统架构师）架构设计、模块划分
cc-algoClaude CodeClaude #2（算法专家）算法、数学建模
cc-codeClaude CodeClaude #3（代码实现）代码生成、测试
cdx-reviewCodexCodex（代码审查员）代码审查、安全审计
💡 最少 3 个 Agent才能形成有效对抗验证。2 个输出 + 1 个审查者是最低配置。

5. 工作流详解

5.1 完整数据流

用户任务
  ├─→ Agent A (--session-id UUID-a) ─→ [完整产出] ─→ extract 结论A
  ├─→ Agent B (--session-id UUID-b) ─→ [完整产出] ─→ extract 结论B
  └─→ Agent C (--session-id UUID-c) ─→ [完整产出] ─→ extract 结论C
      │
      ▼ 所有结论到齐 → 自动触发 Round 2
      │
 结论对比表: | A | 结论A | | B | 结论B | | C | 结论C |
      │
  ├─→ Agent A (--resume UUID-a) → 读结论表 → 评判各方 → 新结论A'
  ├─→ Agent B (--resume UUID-b) → 读结论表 → 评判各方 → 新结论B'
  └─→ Agent C (--resume UUID-c) → 读结论表 → 评判各方 → 新结论C'
      │
      ▼ 所有辩论到齐 → 自动触发 Round 3
      │
  ├─→ Agent A (--resume UUID-a) → 读辩论汇总 → 投票 → 最终建议
  ├─→ Agent B (--resume UUID-b) → 读辩论汇总 → 投票 → 最终建议
  └─→ Agent C (--resume UUID-c) → 读辩论汇总 → 投票 → 最终建议
      │
      ▼ 🏆 最终决策展示

5.2 状态机

状态触发动作
idle初始等待用户
round_1_produce用户提交任务并行启动所有 Agent
round_2_debate全部 R1 完成构建结论表 → 并行辩论
round_3_decide全部 R2 完成构建辩论汇总 → 并行决策
complete全部 R3 完成展示最终决策
⏱ 每轮自动推进，无需手动操作。用户可随时「取消」。

5.3 查看完整产出

「对话」标签 → 每个 Agent 消息下有 ▶ 查看完整产出 折叠区（最多 5000 字）。完整 session 记录在 .multi-ai-workflow/sessions/{agentId}.json。

6. Agent 协议

6.1 结论提取

Dashboard 在每个 Agent stdout 中查找：

──結論──
<结论文本，200 字以内>
────────

没有标记时，回退取最后 500 字。

6.2 自动追加的协议指令

## 工作协议

1. 请在你的完整产出末尾，以以下格式给出 200 字以内的结论摘要：
──結論──
<核心方案、关键决策、注意事项>
────────

2. 结论必须简洁——其他 agent 只会阅读你的结论，不会阅读你的完整产出。

7. Session 持久化

7.1 跨轮次上下文保留机制

CLIRound 1Round 2/3存储位置
Claude Code--session-id <UUID>--resume <UUID>~/.claude/
Codexcodex exec（自动生成 ID）codex exec resume <ID>~/.codex/

7.2 已验证：上下文确实保留

实测结果（双摆模拟测试）：

  • Round 2 中 cc-1 精确引用了自己 Round 1 的三项混沌验证方案
  • Round 2 中 cc-2 精确引用了 cc-1 的拉格朗日推导 + RK45 方案
  • Round 3 中 cc-2 明确说「文件权限问题而非技术失败，代码已就绪可运行」——它记得 Round 1 被权限卡住
  • Round 3 决策综合了三个轮次所有 Agent 的观点
⚠ Claude Code 原生 session 有 ~30 天闲置后可能清理。Dashboard 的 session store（.multi-ai-workflow/sessions/）是永久保存的。

7.3 崩溃恢复

  1. 重启 Dashboard
  2. 自动读取 .multi-ai-workflow/sessions/ 下的 session 元数据
  3. 恢复每个 Agent 的 nativeSessionId
  4. 下次调用自动 --resume → 完整上下文恢复

8. 使用场景

算法设计

设计一个支持 O(log n) 范围查询和更新的数据结构，
用于股票价格区间最值查询。TypeScript 实现 + 复杂度证明。

Agent 建议：1 算法专家 + 1 数据结构专家 + 1 代码审查者

数学建模

建立传染病 SIR 模型，模拟疫苗接种率变化下的传播。
推导微分方程、参数敏感性分析、生成可视化的 Python 脚本。

Agent 建议：1 数学建模专家 + 1 数值仿真专家 + 1 验证者

代码审查

审查 src/engine/ 目录的 Python 代码，
找出性能问题、安全隐患、非 Pythonic 写法。

Agent 建议：2 代码审查者 + 1 安全审查者

嵌入式 / 电赛

STM32 PWM 电机控制：PID 自整定、编码器反馈、串口调试。
C 语言 + HAL 库。

Agent 建议：1 嵌入式专家 + 1 控制算法专家 + 1 代码实现者

系统架构

设计 10 万 QPS 实时消息推送系统。
架构图、技术选型、数据流、容错方案。

Agent 建议：1 架构师 + 1 网络专家 + 1 可靠性工程师

9. 常见问题

启动

Cannot find module 'electron' 
rm -rf node_modules package-lock.json
set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
npm install
窗口一闪而过 
npx tsc -p tsconfig.electron.json   # 查编译错误
ls dist-electron/main.js            # 检查输出是否存在

Agent

Agent 旁出现 ⚠ 图标（CLI 未找到）

PATH 中找不到 CLI。解决方法：

# 1. 确认 CLI 已安装
claude --version
codex --version

# 2. 若未安装
npm install -g @anthropic-ai/claude-code

# 3. 或手动指定完整路径
# Windows 常见路径：
# Claude: %LOCALAPPDATA%\Microsoft\WinGet\Packages\Anthropic.ClaudeCode_*\claude.exe
# Codex:  %LOCALAPPDATA%\OpenAI\Codex\bin\{hash}\codex.exe
Agent 执行卡住不动

可能原因 | 检查方法

  • API 密钥未设 → echo %ANTHROPIC_API_KEY%
  • 网络问题 → 手动测试 claude -p "hello"
  • CLI 进程卡死 → 点「取消」终止
  • 超时（5 分钟） → 任务太复杂，拆分或增加超时
Agent 返回 exit code 1
错误信息原因解决
Invalid session ID不是有效 UUIDDashboard 自动生成，手动测试用 uuidgen
--resume requires valid sessionSession 不存在确保 Round 1 先成功
Authentication requiredAPI 密钥未设claude login 或设置环境变量
Permission denied工具调用需批准Dashboard 用 --permission-mode bypassPermissions
结论没有被正确提取

Agent 输出中没有 ──結論── 标记。Dashboard 回退取最后 500 字。协议指令已在 prompt 中，大多数 Agent 会遵守。某些 Agent 偶有遗漏属正常。

一个 Agent 拖慢全局

流程等待所有 Agent 完成才进入下一轮。解决方法：关闭慢的 Agent（ON→OFF）、点「取消」重试、或用更快的模型（Haiku）。

Codex Round 2 恢复失败

可能原因：session ID 提取失败（需正则匹配 JSONL 输出）、session 用了 --ephemeral。排查：codex resume --last --include-non-interactive

Dashboard 崩溃后 Agent 上下文还在吗？

还在。重启 Dashboard 后：

  1. 自动读 .multi-ai-workflow/sessions/ 下的文件
  2. 恢复 nativeSessionId
  3. 下次调用自动 --resume → 完整上下文恢复

实测：Dashboard 重启后 Agent 仍然记得之前所有对话。

我可以中途加 Agent 吗？

可以。但新 Agent 只会参与下一轮。它没有前轮的上下文。建议完整的工作流从头开始用所有 Agent。

Token 消耗有多省钱？

实测（3 Agent × 3 轮）：

传统方式（全文交换）~30,000 token 用于"理解别人"
结论模式~1,200 token
节省96%（25×）

10. 高级配置

10.1 环境变量

变量用途
ANTHROPIC_API_KEYClaude API 密钥
OPENAI_API_KEYOpenAI API 密钥（Codex）
CLAUDE_CODE_PATH手动指定 Claude Code CLI 完整路径
CODEX_PATH手动指定 Codex CLI 完整路径

10.2 CLI 自动发现顺序

  1. 环境变量 CLAUDE_CODE_PATH / CODEX_PATH
  2. PATH 中的 claude / codex
  3. %LOCALAPPDATA%\Microsoft\WinGet\Packages\（winget 安装）
  4. %LOCALAPPDATA%\OpenAI\Codex\bin\（Codex 桌面应用）
  5. %APPDATA%\npm\（npm 全局安装）

10.3 自定义模型

在 agent-manager.ts 的 buildCliArgs 中添加 --model 参数可为不同 Agent 指定模型容量：

// 快 Agent（低成本）
args.push('--model', 'claude-haiku-4-5');
// 强 Agent（高质量）
args.push('--model', 'claude-sonnet-4-6');

10.4 MQTT 外部任务源（可选）

保留的 engine/mqtt_client.py 可从外部 MQTT Broker 接收任务发布到 workflow/tasks/#，适用于 CI/CD 集成。

10.5 Sandbox（可选）

保留的 engine/sandbox.py 可在 Docker/子进程中执行 Agent 产出的 Python 代码，验证正确性。
